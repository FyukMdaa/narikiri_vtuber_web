* このプロジェクトについて
カメラからの入力に対してリアルタイムで骨組みを検出し、モデルに反映します。
* 進捗
- [X] カメラ入力に対して骨組みを認識する
- [X] カメラ入力を画面に表示
- [X] カメラ入力の上に骨組みを上から表示
- [X] vrm1.0/vrm0.xの読み込み
- [X] vrm1.0/vrm0.xをカメラ入力に合わせて動かす
- [X] Inoch2Dに対応
- [ ] Live2Dに対応
- [X] フォト機能の実装
- [X] デスクトップアプリ化 (Tauri: Windows / Linux / macOS)
- [X] MediaPipe の自己ホスト化（CDN非依存）
- [X] MediaPipe を Web Worker + OffscreenCanvas で実行

* セットアップ

** 依存関係のインストール
#+begin_src sh
npm install
#+end_src
~postinstall~ で自動的に MediaPipe のモデルファイル取得を試みますが、
失敗する場合は個別に実行してください:
#+begin_src sh
npm run fetch:mediapipe
#+end_src
これにより以下が用意されます（すべて外部CDNへ依存せず同一オリジンから配信）:
- ~web/js/vendor/mediapipe/~ … ~@mediapipe/tasks-vision~ のESMバンドル + WASM
- ~web/assets/mediapipe/models/~ … face / pose / hand の各 ~.task~ モデルファイル
  （容量が大きいため git 管理外。初回セットアップ時に必ず取得してください）

** ディレクトリ構成
Tauriの ~frontendDist~ は ~node_modules~ や ~src-tauri~ を含んではいけない
という制約があるため、ブラウザに配信するWeb資産一式は ~web/~ 配下に
分離してあります。
#+begin_src text
.
├── web/              ← ブラウザ配信物（index.html, css/, js/, assets/）
│   ├── index.html
│   ├── css/
│   ├── js/
│   └── assets/mediapipe/models/  ← fetch:mediapipe で取得
├── scripts/          ← devサーバ・アセット取得スクリプト (Node)
├── src-tauri/         ← Tauriアプリ (Rust)
└── package.json
#+end_src

** ブラウザで開発 (これまで通り)
#+begin_src sh
npm run dev
#+end_src
[[http://127.0.0.1:1420]] を開いてください。ビルドツール無しの素の ES Modules
構成なので、ブラウザから直接 index.html を読み込む用途でも動作します
（ただし ~file://~ 直接オープンは Worker のモジュール解決の都合上非推奨。
必ず何らかの静的HTTPサーバ経由でアクセスしてください）。

** デスクトップアプリ (Tauri) で開発
前提: [[https://www.rust-lang.org/tools/install][Rust]] と、OSごとのTauri必須パッケージ
（Linux: ~webkit2gtk-4.1~ 等。詳細は [[https://v2.tauri.app/start/prerequisites/][公式Prerequisites]]）。
#+begin_src sh
npm run tauri:dev
#+end_src

** デスクトップアプリのビルド
#+begin_src sh
npm run tauri:build
#+end_src
成果物は ~src-tauri/target/release/bundle/~ 以下に生成されます
(Windows: ~.msi~/~.exe~、macOS: ~.app~/~.dmg~、Linux: ~.deb~/~.rpm~/~.AppImage~)。

*** OS別の注意点
- *macOS*: カメラ利用の許可ダイアログを正しく出すため、
  ~src-tauri/Info.plist~ に ~NSCameraUsageDescription~ を定義済みです
  （tauri-build が自動でマージします）。配布用に正式署名・notarize
  する場合は別途 Apple Developer 証明書が必要です。
- *Linux*: ~getUserMedia~ の対応状況は distro の webkit2gtk バージョンに
  依存します。動作しない場合は ~webkit2gtk~ を最新化してください。
- *Windows*: 初回起動時に WebView2 ランタイムが無い場合、
  ~webviewInstallMode: downloadBootstrapper~ の設定によりインストーラが
  自動でランタイムを取得します。

** CI / GitHub Actions
~.github/workflows/tauri-build.yml~ が push / PR / ~v*~ タグ push で
Windows・Linux(ubuntu-22.04)・macOS(universal) 向けに自動ビルドします。
~v*~ タグを push すると、ビルド成果物付きの Draft Release が自動作成
されます（そのまま公開するかは手動で確認してください）。

* アーキテクチャ変更点 (MediaPipe)

- ~web/js/vendor/mediapipe/~ にESM/WASMバンドルを自己ホスト
  （~jsdelivr~・~storage.googleapis.com~ へは実行時アクセスしません）。
- 実際の検出処理 (FaceLandmarker / PoseLandmarker / HandLandmarker) は
  ~web/js/tracking/mediapipe-worker.js~ という専用 Web Worker 内で実行され、
  メインスレッド (UI/描画) をブロックしません。
  - Worker には ~document~ が存在しないため、GPUデリゲート使用時は
    tasks-vision が内部で ~OffscreenCanvas~ を用いて描画コンテキストを
    確保します（ブラウザネイティブ機能）。GPU非対応環境では自動的に
    CPUデリゲートへフォールバックします。
  - メインスレッドは ~<video>~ から ~createImageBitmap()~ でフレームを
    切り出し、所有権ごと ~postMessage~ で Worker へ転送（ゼロコピー）
    します。検出結果（ランドマーク等）はJSONシリアライズ可能な
    プレーンオブジェクトとして送り返されます。
  - ~web/js/camera/trackers.js~ がPromiseベースのRPCレイヤーとして
    Workerとの通信を仲介し、~web/js/tracking/detection-loop.js~ は
    1フレーム分の検出が完了するまで次のフレームを投げない
    バックプレッシャー制御を行うことでキュー溜まりを防いでいます。

* フォト機能

スペースキーまたはツールバーの「撮影」ボタンで、その瞬間のアバター・カメラ映像・骨組み
をキャプチャし、1 枚の静止画として保存・転送できる機能です。

** 使い方
1. ツールバー右側のレイアウトセレクタで構成を選びます。
   - カメラ + アバター: カメラ映像とアバターを横並び
   - アバターのみ: アバター単体
   - アバター + 骨組み: アバターと骨組み（トラッキング可視化）を横並び
   - カメラ + 骨組み + アバター: カメラ映像に骨組みをオーバーレイしたものとアバターを横並び
2. ~Space~ キー または「撮影」ボタンを押す。
3. モーダルが開き、左に撮影したフォト、右にデータ転送用のアニメーションQRが表示される。
4. 受信側（もう一台の端末）のカメラで QR を読み取ると画像が転送される。

** カメラ表示を隠している場合
「映像を隠す（骨組みのみ）」モード中はカメラ必須のレイアウトが選択肢から自動的に除外
され、「アバターのみ」「アバター + 骨組み」の 2 種類だけが選べます。

** env 設定（フォトフレームの文字列）
フォトフレームに描画される文字列はプロジェクトルートの ~.env~ ファイルに隔離されて
います。~npm run dev~ または ~npm run tauri:build~ 実行時に ~scripts/inject-env.mjs~
が ~.env~ を読み込んで ~web/js/env.js~ を生成します。フロントエンドのコードからは
~.env~ を直接参照せず、生成された ~env.js~ を ~import~ して利用します。

#+begin_src sh
# .env の編集例
PHOTO_FRAME_TEXT=なりきりVTuber
PHOTO_FRAME_SUBTEXT=Photo Mode
PHOTO_FRAME_COLOR=#3b82f6
PHOTO_FILE_PREFIX=vtuber-photo
#+end_src

** QR 転送ライブラリ（オフライン動作）
~https://github.com/ymuichiro/animated_data_qr_js~ をビルド時に組み込み、
~web/js/vendor/animated-data-qr/~ 配下に配置済みです。実行時に外部 CDN への
依存は発生しません。~compatibility~ プリセット（QR 誤り訂正レベル M、
1 フレーム 1 シンボル）を使用し、受信側の環境に依存しにくい設定にしています。
